# Davis deployment instructions

This is a thin regional consumer of `region-intel`. Keep generic methods, API,
UI, tests of algorithms and manuscript tooling in the shared repository. This
repository owns public JSON configuration, regional evidence and deployment
orchestration. Use Bun and the exact Git dependency pin; do not add a sibling
filesystem dependency to a published manifest.

Read `docs/sources.md` before changing local policy. Every enabled monitor must
have reviewed regional configuration. Disabled coastal fields required by the
v1 schema are not Davis coverage. Do not enable a provider by relabelling its
Crescent output. Keep output, corpus/vector namespaces and calendar identities
independent. A configured source is not proof of successful collection.

Run `bun run validate`, `bun run pages:export`, and `bun run pages:validate` for
consumer changes. Core qualification belongs to the matching shared-package
commit. Never fabricate a Davis code seed, source freshness, model output or
manuscript result. Preserve raw failed evidence and separate local validation
from hosted deployment. Follow the ancestor GitVault repository lease contract.
